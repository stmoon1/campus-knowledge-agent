# 实际评估

在 Windows 上使用 Node.js v24.22.1 和本机 Ollama Qwen3:8B（Q4_K_M）运行。自动化测试 11/11 通过，见 [TAP 日志](../examples/test-results.tap)。六组 Mock 输出见 [examples/mock](../examples/mock)，不用于证明真实模型的决策能力。

| 场景 | 真实模型行为与结果 | 实际记录 |
| --- | --- | --- |
| 明确答案 | 搜索命中 D05，读取后回答访客登记规则 | [01](../examples/ollama/01-answer.json) |
| 文档冲突 | 搜索命中两个版本，读取 D01 和 D02，模型选择报告冲突，输出两段原文并请求确认 | [02](../examples/ollama/02-conflict.json) |
| 资料外问题 | 检索没有相关记录，模型请求提供资料，不生成答案 | [03](../examples/ollama/03-out-of-scope.json) |
| 改写问法 | 根据改写后的请假问题找到 D03，回答申请时间 | [04](../examples/ollama/04-paraphrase.json) |
| 上下文追问 | 根据前文补全“那找谁批”，最后引用 D04 回答直属主管审批 | [05](../examples/ollama/05-follow-up.json) |
| 工具失败 | 搜索成功，读取返回模拟故障，模型说明无法读取并请求补充，结果保持未完成 | [06](../examples/ollama/06-tool-failure.json) |

上述六条覆盖第 3 题列出的六个场景。记录 01 与 02 可直接比较不同的下一步和最终动作。记录 06 展示读取失败后的第三条路径。单组耗时约 1.8–4.6 秒，含 CLI 进程启动与模型服务响应，仅代表该机器的这轮记录。

## 迭代前后

首次实跑中，模型曾漏读冲突版本，被运行器拦截；也曾在年假追问中要求用户重复交代主题。见 [冲突基线](../examples/baseline/02-conflict.json) 和 [追问基线](../examples/baseline/05-follow-up.json)。调整后明确区分历史与当前问题，补充追问示例；当模型提前尝试回答而缺少原文时，把缺失文档 ID 作为观察交给模型，允许它在总步数预算内修正。最终重新运行全部用例，结果见上表。

## 限制

词表检索可能漏掉全新表达，当前用例规模很小，未评估企业级召回率或模型稳定性。同主题不同文本按可能冲突处理，无法自动识别等义改写。故障由测试输入注入，本项目未测生产级恢复或并发。
