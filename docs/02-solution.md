# 方案

模型每轮只返回一项结构化动作。运行器校验动作、参数和步数，再执行本地检索或原文读取。观察以 JSON 写入下一轮消息，模型可以继续搜索、读取、请求补充、返回冲突或结束。动作依据是面向评审的简短说明。

检索使用规范化词表匹配，返回命中主题的所有版本。模型负责从改写问题或上下文中抽取检索词。原文只能通过已命中文档 ID 读取。输出从实际读取的条款构建，模型无法自行写引文。如果模型试图跳过同主题的其他版本，运行器把尚未读取的文档 ID 交回模型，由模型决定如何修正；如果已读完但原文不同，运行器返回冲突。合成数据里每条片段是一条完整的制度条款，不用日期代替适用范围或优先级。

实现使用 Node.js 原生 fetch 和测试运行器，省去框架与外部依赖。Ollama 仅连接本机。CLI 输出 JSON，便于比较状态、文档 ID 和 Trace。
